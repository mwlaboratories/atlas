#+title: Atlas

Split ergonomic keyboard, Choc V2 + MX keycaps, 34 keys, BLE wireless. Each
half has its own XIAO nRF52840 Plus controller. A later branch adds an
ADS1220 strain-gauge trackpoint between cols 3–4 (atlas's signature).

This branch (=main=) is a clean restart with a disjoint history. The
previous work is preserved as tags:

- =proto/breakout-v1= — the breakout-board prototype currently in daily use
- =bench/ads1220= — bench-proven ADS1220 strain-gauge firmware

* Current direction (2026-05-24)

End-to-end ergogen-driven PCB generation, driven from the local webtool.
The flow:

#+begin_src
  tools/layout/index.html      atlas layout editor (Totem → Choc V2 remix,
       │                        per-col splay/stagger/y, thumb cluster)
       │  POST /api/build
       ▼
  tools/server.mjs             Express dev server. Receives layout state,
       │                        calls layoutToErgogen() → YAML.
       ▼
  ergogen (Node JS API)        Generates KiCad 8 .kicad_pcb with
       │                        switch + diode + LED placed per key,
       │                        matrix nets wired, edge cuts shaped.
       ▼
  pcb/kicad/keyboard.kicad_pcb KiCad 10 reads this directly.
       │
       ▼
  kicad-cli pcb render         Top + bottom PNGs, shown in webtool
                               as visual feedback.
#+end_src

Status: pipeline works end-to-end. Static config produces a clean 34-key
split. The webtool's "build PCB" button works, but =layoutToErgogen()=
math is partially wrong (per-column shifts off, thumbs disconnected).
Static config in =tools/ergogen/config.yaml= is the working reference.

* History / what didn't work

This branch went through three strategy pivots before landing on ergogen.
Documented so a fresh session doesn't relitigate them:

** First attempt: KiCad GUI + custom pcbnew Python scripts (=add_leds.py=, =mirror_to_right.py=, =atlas_pcb.py=)

Hit a sequence of subtle bugs in =pcbnew.SetOrientationDegrees()= where
repeated rotation operations accumulated drift on pad and property
local-frame rotations (LED pads ended up at non-cardinal angles like
201° instead of the library's 180°). The world render still looked
correct, but the footprint editor showed funky angles because the
=footprint_anchor + pad_local= sum was right but neither term was clean.

Also wrong: my custom switch-rotation normalization "fix" rotated all 34
switches because the heuristic was too broad — only the non-cardinal
thumb keys needed correction. The Choc hotswap is 180°-rotationally
symmetric so the bug was invisible until LED chamfered corners and
diode polarity revealed it.

*Lesson:* don't write custom pcbnew rotation scripts. Either use
kbplacer (proper GUI plugin) or skip KiCad-the-tool entirely (current
ergogen path). [[file:~/.claude/projects/-home-gomar-Documents-repos-atlas/memory/project_led_diode_mirror_bug.md][Memory has full details.]]

** Second attempt: EasyEDA Pro pivot

Considered moving the design to EasyEDA Pro for native JLCPCB
integration. Spent time finding the Choc hotswap, LED, diode in LCSC.
Reasonable workflow on paper:

- Build one "key" Reuse Block (switch + diode + LED + ports)
- Instantiate 34×
- Place each via the JS Extension API

Abandoned because the keyboard-specific tooling lives in KiCad
(kbplacer, kiswitch, Replicate Layout, ergogen) and EasyEDA's keyboard
ecosystem is barely-existent. The unfamiliarity tax + community size
made this strictly worse than learning ergogen.

** Third / current attempt: ergogen end-to-end

Use ergogen's Node API directly from a small Express server. Output is
KiCad 8 format (ergogen's =template: kicad8=), which KiCad 10 reads
cleanly. Renders via =kicad-cli pcb render=. Webtool gets a "build PCB"
button that drives the whole thing and shows the result inline.

This is the approach used by Totem, Corne v3+, Cygnus, and basically
every modern community split keyboard. We're not inventing anything new
here.

* Conventions

- Layout source of truth: =pcb/keyboard.json= (exportable from webtool, KLE-ish).
- Coordinate convention: atlas-y goes DOWN (KLE convention); ergogen-y goes
  UP. The translator negates Y when bridging.
- Per-key pose: switch position from layout, diode at switch-local =(−6, −4)=
  rotation =+90°=, LED at switch-local =(0, +4.93)= rotation =0°=. These are
  baked into =tools/ergogen/config.yaml=.
- Footprint library: ceoloide/ergogen-footprints (vendored in
  =tools/ergogen/footprints/= so we don't depend on git submodules).
- Halves are mirrored via ergogen's =points.mirror=; we don't author the right
  half — ergogen generates it.
- 34 keys total: 17 per half = 15 alpha (5×3) + 2 thumb.
